## **🛠️ Блок В: Специфікація для Resizable Chat Drawer**

Панель чату розміщена з правого боку екрана. Коли користувач перетягує ресайзер ліворуч, координата курсора X (clientX) зменшується, а ширина чату збільшується.

### **📐 Математична модель обмежень**

* **\\text{Min}**: 380\\text{px}  
* **\\text{Max}**: 50\\% від window.innerWidth

### **🚨 Інженерні «Gotchas» та їх превентивне усунення:**

1. **D3.js Layout Crash (Критично):** В релізі v1.0.0-release ми локалізували D3.js. SVG-графіки не мають властивості responsive: true, як Chart.js. Якщо викликати тригер resize на кожен піксель руху миші, інтерфейс Mac M4 застигне через лавину перерахунків SVG-шляхів.  
   * *Рішення:* Під час перетягування (mousemove) змінюється **тільки** CSS-змінна за допомогою requestAnimationFrame. Глобальна подія window.dispatchEvent(new Event('resize')) викликається **суворо один раз** у момент mouseup.  
2. **UX Текстовий Glitch:** Випадкове виділення тексту дашборду під час драгу.  
   * *Рішення:* Клас .dragging-chat з інжекцією user-select: none \!important на body під час активного захвату межі.

### **📋 Специфікація коду для static/js/ui.js**

export function initChatResizer() {  
    const resizer \= document.getElementById('chat-resizer');  
    if (\!resizer) return;

    let isDragging \= false;

    resizer.addEventListener('mousedown', (e) \=\> {  
        isDragging \= true;  
        document.body.classList.add('dragging-chat');  
        e.preventDefault();  
    });

    window.addEventListener('mousemove', (e) \=\> {  
        if (\!isDragging) return;  
          
        requestAnimationFrame(() \=\> {  
            let newWidth \= window.innerWidth \- e.clientX;  
            const maxWidth \= window.innerWidth / 2;  
              
            if (newWidth \< 380\) newWidth \= 380;  
            if (newWidth \> maxWidth) newWidth \= maxWidth;  
              
            document.documentElement.style.setProperty('--chat-width', \`${newWidth}px\`);  
        });  
    });

    window.addEventListener('mouseup', () \=\> {  
        if (\!isDragging) return;  
        isDragging \= false;  
        document.body.classList.remove('dragging-chat');  
          
        // Безпечний одноразовий рендеринг D3 та Chart.js  
        window.dispatchEvent(new Event('resize'));  
    });  
}

## **👑 Блок А: Специфікація RBAC, Google Auth, Телеметрія та Подвійна RAG-архітектура**

Це ядро переходу системи від локального скрипта до **Multi-tenant SaaS**\-платформи.

### **1\. Подвійна RAG-система та Оптимізація пам'яті Агента**

Для запобігання змішування контекстів та економії токенного бюджету (Token Budget) ми створюємо дві абсолютно ізольовані RAG-пам'яті.  
                        \[АРХІТЕКТУРА ПОДВІЙНОЇ RAG-ПАМ'ЯТІ\]  
                                         │  
               ┌─────────────────────────┴─────────────────────────┐  
               ▼                                                   ▼  
┌──────────────────────────────┐                    ┌──────────────────────────────┐  
│     ВНУТРІШНЯ RAG-ПАМ'ЯТЬ     │                    │     ЗОВНІШНЯ RAG-ПАМ'ЯТЬ     │  
├──────────────────────────────┤                    ├──────────────────────────────┤  
│ • Ціль: Розвиток проєкту    │                    │ • Ціль: Дашборд-Асистент     │  
│ • Сховище: \`agent\_context/\`  │                    │ • Сховище: SQLite \+ Vector   │  
│ • Доступ: Тільки АДМІН       │                    │ • Доступ: АДМІН / ЮЗЕР (Read)│  
└──────────────────────────────┘                    └──────────────────────────────┘

#### **📂 Система 1: Внутрішня RAG-пам'ять (Для подальшої розробки проєкту)**

* **Суть:** Зберігає архітектурну пам'ять, лог розробки, правила поведінки та технічні рішення (CONTEXT.md, development\_log.md, AGENT\_RULES.md).  
* **Оптимізація:** Тільки **Адмін** через свій чат має право вносити сюди правки або ініціювати оновлення індексів. Дані зберігаються у вигляді структурованого Markdown у директорії agent\_context/. При завантаженні нового розробника-агента, ці файли зчитуються першими за допомогою механізму Memory Pointers.

#### **🗄️ Система 2: Зовнішня RAG-пам'ять (Для AI-помічника в дашборді)**

* **Суть:** Зберігає знання про контент: аналітику новин, тренди каналів, зведення N-грам та метадані 18k+ відео.  
* **Оптимізація (Sliding Window & Векторизація):**  
  * Переписки **Адміна** автоматично векторизуються за допомогою легких ембеддінгів та зберігаються в таблиці rag\_knowledge\_base через розширення sqlite-vss або повнотекстовий індекс FTS5 в SQLite.  
  * Переписки **Юзера** ізолюються у межах його сесії (session\_id), зберігаються в DOM (dataset.raw) і **ніколи** не потрапляють у загальну базу RAG, що запобігає забрудненню «мозку» платформи.

### **2\. Рольова модель (RBAC) та Обмеження**

* **Адмін (Макс. 4 особи):** Повний доступ до PTY-терміналу, зміна провайдерів AI (Gemini, OpenAI, Ollama), генерація інвайтів, перегляд графіків телеметрії сервера.  
* **Юзер (Аналітик):** Блокування вкладки "Terminal", приховання важких роутів скрапінгу (/api/action/scrape, /api/action/update) для захисту від бана IP. Модель чату зафіксована бекендом (наприклад, gemini-2.5-flash) без права вибору провайдера.

### **4\. Модуль Телеметрії (Заміри під хмару)**

import psutil  
import time  
from app.models import DatabaseClient \# Наш існуючий клієнт

def system\_telemetry\_worker():  
    \# Режим WAL забезпечує безпечний паралельний запис метрик  
    db \= DatabaseClient()   
    while True:  
        cpu \= psutil.cpu\_percent(interval=0.5)  
        ram \= psutil.virtual\_memory().used / (1024 \* 1024\) \# MB  
        disk \= psutil.disk\_io\_counters()  
        disk\_io \= disk.write\_bytes \+ disk.read\_bytes  
          
        db.execute("""  
            INSERT INTO system\_metrics (cpu\_percent, ram\_mb, disk\_io\_bytes, active\_connections)  
            VALUES (?, ?, ?, ?)  
        """, (cpu, ram, disk\_io, 1)) \# active\_connections рахуємо через Flask session counters  
          
        time.sleep(10) \# Замір кожні 10 секунд
