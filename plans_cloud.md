# 🗺️ План хмарної інтеграції бази даних

Цей документ описує стратегію перенесення та бекапу бази даних проекту у хмару, відповідно до обраного поетапного підходу.

---

## 📅 Етап 1 (Поточний): Резервне копіювання на Kaggle Datasets
Для збереження поточної локальної архітектури SQLite ми впроваджуємо модуль резервного копіювання на Kaggle.

### Як це працює:
1. Користувач створює токен Kaggle API (`kaggle.json`) та додає його у систему.
2. Після закінчення скрапінгу (наприклад, у `scrape_multi.py`) скрипт викликає модуль бекапу.
3. Модуль стискає локальний файл `data/youtube_news.db` та завантажує його через Kaggle API як нову версію приватного датасету.
4. Додається функція відновлення: можливість вивантажити (скачати) останню версію файлу бази даних з Kaggle назад на локальну машину.

---

## 📅 Етап 2 (Перспектива): Міграція на Cloud PostgreSQL (Supabase / Neon)
Коли база даних стане великою, або коли з'явиться потреба в аналітиці в реальному часі, ми проведемо міграцію на повноцінну хмарну реляційну СКБД.

### Як це працюватиме:
1. Дзеркалювання даних: Локальний скрапер продовжуватиме писати в SQLite, але після кожної пачки синхронізуватиме лише нові/змінені рядки (дельта-завантаження) у PostgreSQL.
2. Прямий доступ: Дані у Supabase стануть доступними для підключення BI-систем (PowerBI, Tableau) чи веб-панелей напряму через стандартний SQL-порт.
3. Оптимізація трафіку: Відпаде потреба щоразу ганяти гігабайтний файл SQLite по мережі.
